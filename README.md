# OpenGL 좌표계 변환 실습 18~23

제공된 **OpenGL 기초, GLSL 기초 1·2, 좌표계 변환 1·2**와 실습 18~23 PDF를 바탕으로 작성한 C++17 / OpenGL 3.3 Core 프로젝트입니다. 각 실습은 별도의 Visual Studio 프로젝트와 실행 파일을 갖습니다. 공통 코드와 셰이더에도 한국어 설명 주석이 있습니다.

## 실행하기

1. 상위 폴더의 `컴그.slnx`에서 **실습 18~23 (좌표계 변환)** 그룹을 펼칩니다. 이 폴더의 `Coordinates18_23.sln`으로 새 실습 6개만 열 수도 있습니다.
2. 구성을 **Debug / x64**로 선택합니다. 도구 집합은 설치된 VS 2022의 **v143**입니다.
3. 실행할 `Practice18`~`Practice23`을 오른쪽 클릭해 **시작 프로젝트로 설정**합니다.
4. **Ctrl+F5**로 실행합니다. 전체 빌드는 **Ctrl+Shift+B**입니다.

폴더의 `Run_Practice18.cmd`~`Run_Practice23.cmd`를 더블 클릭해도 됩니다. 실행 파일이 없으면 먼저 전체 빌드를 합니다. `BUILD.cmd`로 빌드만 할 수도 있습니다.

```powershell
.\build.ps1                 # Debug x64 전체 빌드
.\build.ps1 -Test           # 빌드 + 수학/시뮬레이션 검사 + OpenGL 실행 검사
.\build.ps1 -Configuration Release
```

필요 환경은 **Windows x64, Visual Studio C++ 데스크톱 개발 워크로드, Windows SDK, OpenGL 3.3 지원 드라이버**입니다. GLFW 3.5.1 / GLEW 2.3.1 / GLM 1.0.3은 이 컴퓨터에 있던 공식 배포 파일에서 프로젝트 안으로 복사했습니다. 절대 경로 설정, 인터넷 다운로드, 별도 패키지 설치가 필요 없습니다. 실행 폴더로 `glew32.dll`, `vertex.glsl`, `fragmet.glsl`이 자동 복사됩니다. 실행 파일을 옮길 때는 이 파일들도 함께 옮겨야 합니다.

## 각 실습의 소스는 3개

```text
practice18/                 (19~23도 같은 구성)
  main.cpp                  상태, 초기화, 셰이더 로딩, 도형, 입력, 렌더링, main
  vertex.glsl               정점 위치 변환과 색상 전달
  fragmet.glsl              프래그먼트 색상 출력
```

파일명은 요청하신 **`fragmet.glsl`**을 그대로 사용했습니다. 각 프로젝트는 `main.cpp` 하나만 컴파일하며, 추가 사용자 헤더나 공통 cpp 파일을 include하거나 연결하지 않습니다. `.vcxproj`/`.filters`는 Visual Studio 프로젝트 설정 파일입니다.

GLFW/GLEW/GLM과 C++ 표준 라이브러리는 기존처럼 사용합니다. 필요한 보조 함수도 모두 해당 실습의 `main.cpp` 안에 있습니다. 각 실습의 두 GLSL을 개별 파일로 두어 한 실습의 셰이더를 수정할 수 있습니다.

## main.cpp 읽는 순서

1. 라이브러리, `Vertex`/`Mesh`, GLM 변환 함수와 선언
2. 셰이더 컴파일·링크, VAO/VBO/EBO, 도형 그리기
3. 탱크 구성 (실습 19·22)
4. 실습별 상태, `ResetScene`, `UpdateScene`, `HandleKey`, `DrawScene`
5. `KeyCallback`/`Reshape`/마우스 콜백과 `main`

각 연산에 **개념·사용 방법·사용 이유**를 한국어 주석으로 작성했습니다. 실습 9~17의 구조체·배열·일반 함수 흐름을 유지했습니다. `MakeMove`, `MakeRotate`, `MakeScale`, `SendTransform`도 같은 파일에서 확인할 수 있습니다.

기초 자료와 코드의 연결은 `강의_개념과_코드.md`, 기존 실습 9~17과의 연결은 `실습9_17_작성방식_대응.md`에 정리했습니다.

## 실습 18: 태양·행성·달

중앙 구, 서로 다른 색·속도의 행성 3개, 행성마다 달 1개를 그립니다. 행성 궤도는 xz 평면, 그 평면의 +45° / -45° 기울기입니다. 공전 경로도 모두 표시합니다. 깊이 테스트와 투영을 적용합니다.

| 키 | 동작 |
|---|---|
| `p` / `Shift+p` | 직각 투영 / 원근 투영 |
| `m` / `Shift+m` | 솔리드 / 와이어프레임 |
| `w/a/s/d` | 전체 태양계를 +y/-x/-y/+x로 이동 |
| `+` / `-` | 전체 태양계를 +z / -z로 이동 |
| `1` | 행성·달 궤도 반지름을 원래 크기 / 확대 크기로 전환 |
| `2` | 중심 구의 크기·색상 변화 시작 / 정지 |
| `3` | 행성 z축을 기준으로 달 궤도 회전 시작 / 정지 |

**핵심:** `R * T`는 떨어진 위치를 원점 주위로 돌리는 공전입니다. 달은 행성 위치를 부모로 사용합니다. 달의 초기 궤도면은 뷰 회전의 역행렬로 카메라 화면과 평행하게 맞춥니다. `3`번을 켜면 이 궤도면에 추가 회전을 적용합니다.

## 실습 19: 탱크와 카메라

바닥, 아래 몸체 2개, 중앙 몸체, 상부 몸체 2개, 각 상부의 포신·깃대를 육면체로 구성합니다. 바닥 경계에서 탱크의 이동을 제한합니다.

| 키 | 동작 |
|---|---|
| 방향키 | xz 평면에서 탱크 이동 |
| `d` | 아래 몸체 y축 확대·축소 시작 / 정지 |
| `t` | 중앙 몸체 y축 회전 시작 / 정지 |
| `l` | 상부 몸체 둘의 위치 교환 / 복귀 |
| `g` | 양쪽 포신의 반대 방향 y축 회전 시작 / 정지 |
| `p` | 양쪽 깃대의 반대 방향 x축 회전 시작 / 정지 |
| `z` / `Shift+z` | 카메라 z축 양 / 음 이동 |
| `x` / `Shift+x` | 카메라 x축 양 / 음 이동 |
| `y` / `Shift+y` | 카메라 로컬 y축 시계 / 반시계 자전 애니메이션. 같은 키를 다시 누르면 정지 |
| `r` / `Shift+r` | 장면 중심 y축 시계 / 반시계 공전 애니메이션. 같은 키를 다시 누르면 정지 |
| `o` | 몸체 색 변경 |
| `c` | 전체 초기화 |

**핵심:** 부품을 부모 행렬에서 파생시켜 함께 움직이게 합니다. 부품의 크기 변환은 자식에게 상속하지 않아 포신이나 깃대의 길이가 왜곡되지 않게 합니다. 포신과 깃대는 연결점으로 이동한 뒤 회전합니다. 카메라 자전은 위치가 고정되고, 공전은 위치가 바뀝니다.

## 실습 20: 택배 물류 센터

xz 바닥 위의 ㄱ자 컨베이어를 평면으로 만들고, 육면체 줄무늬와 번호가 있는 서로 다른 색의 상자 5개를 배치합니다. 90° 코너는 그림처럼 직선 두 개가 만나는 각진 ㄱ자로 만들었습니다. 벨트와 상자는 같은 경로 거리로 이동하며 끝에서 시작으로 돌아갑니다.

| 키 | 동작 |
|---|---|
| `b` | 벨트 시작 / 정지 |
| `+` / `-` | 카메라 가까이 / 멀리 |
| `p` / `Shift+p` | 원근 / 직각 투영 |
| 왼쪽 / 오른쪽 방향키 | 중심 y축 기준 카메라 시계 / 반시계 회전 |
| `r` | 초기화 |

**핵심:** 누적 이동 거리로 두 직선 중 어느 구간인지 정합니다. 코너 부근에서는 각도를 180°에서 90°로 연속적으로 보간해 상자도 진행 방향을 따라 회전합니다. 번호는 육면체 7세그먼트라 글꼴·텍스처가 필요 없습니다.

## 실습 21: 3차원 공 튕기기

서로 다른 색의 왼쪽·오른쪽·바닥·천장·뒷벽을 평면으로 그립니다. 앞면은 열려 있습니다. 구와 벽, 구와 바닥의 상자가 충돌하면 반사합니다. 서로 크기가 다른 상자 3개를 z축에 나란히 배치했습니다. 방을 z축으로 기울이면 상자도 회전하고 기울어진 바닥을 따라 미끄러집니다.

| 키·마우스 | 동작 |
|---|---|
| `Shift+b` (`b`도 허용) | 새 공 추가, 최대 5개 |
| `z` / `Shift+z` | 장면 z축 양 / 음 이동 |
| `y` / `Shift+y` | 화면 y축 시계 / 반시계 회전 |
| 왼쪽 버튼 드래그 | 방 z축 회전과 상자 미끄러짐 |
| `o` | 바닥 열기 / 닫기 **(자료에 키가 없어 추가한 보조 명령)** |
| `c` | 초기화 **(추가 명령)** |

**핵심:** 방 바깥쪽 기준으로 만든 면의 앞면을 컬링하면 안쪽이 보입니다. 충돌은 방의 로컬 좌표에서 검사하고 중력 방향만 역회전해 계산합니다. 눈에 보이지 않는 앞쪽에도 공을 공간 안에 유지하는 충돌 경계를 둡니다. 바닥이 열리면 바닥 충돌을 해제해 공과 상자가 아래로 떨어집니다. 떨어진 객체는 `c`로 복원합니다. 공끼리의 충돌은 실습 요구 범위에 없어 구현하지 않았습니다.

## 실습 22: 다중 뷰포트

실습 19와 **동일한 탱크 코드·상태**를 사용합니다. 왼쪽은 원근 투영, 오른쪽 위는 xz 평면도, 오른쪽 아래는 xy 정면도입니다. **실습 19의 조작키를 그대로 사용합니다.** 카메라 조작은 원근도에 적용하고, 평면도와 정면도의 관측 방향은 고정합니다.

**핵심:** 한 번 갱신한 탱크를 `glViewport`와 V/P 행렬을 바꾸며 세 번 그립니다. 각 영역의 종횡비를 사용합니다. 평면도의 시선이 y축과 나란하므로 up 벡터는 `(0,0,-1)`로 설정합니다. 뷰포트마다 깊이 버퍼를 해당 영역에서 초기화합니다.

## 실습 23: 걷는 로봇

서로 다른 색의 육면체 무대 안에서 로봇이 걷습니다. 머리·몸통·팔·다리·코를 육면체로 구성하고 양팔·양다리를 다른 색으로 표시했습니다. 장애물 3개는 크기가 다르고 서로 겹치지 않는 난수 위치에 배치합니다. 시드는 재현 가능하도록 고정했으므로 초기화하면 같은 배치로 돌아옵니다.

| 키 | 동작 |
|---|---|
| `o` | 무대 앞면 열기 / 닫기 |
| `w/a/s/d` | -z / -x / +z / +x 방향으로 바꿔 걷기 |
| `+` / `-` | 걷는 속도와 팔다리 흔들림 각도 증가 / 감소 |
| `j` | 제자리 수직 점프 |
| 공중에서 `w/a/s/d` | 점프 중 이동 방향 설정. 장애물 위로 올라갈 때 사용 |
| `z` / `Shift+z` | 카메라 z축 양 / 음 이동 |
| `x` / `Shift+x` | 카메라 x축 양 / 음 이동 |
| `y` / `Shift+y` | 장면 중심 y축 기준 카메라 시계 / 반시계 공전 |
| `i` | 모든 상태 초기화 |

**핵심:** 어깨와 골반에 피벗 행렬을 두고 팔·다리를 반대 위상으로 회전합니다. 이동 후보가 경계나 장애물과 충돌하면 그 위치로 이동하지 않고 진행 방향을 뒤집습니다. 점프는 중력과 수직 속도를 적분하며, 하강 중 장애물 윗면을 통과할 때만 착지시킵니다. 장애물 위에서 걸어 나오면 바닥으로 내려옵니다.

앞면 열기는 자료의 '위로 슬라이딩'과 '스케일되어 열림'을 함께 표현하도록 위쪽 경계를 고정하고 높이를 줄입니다. 로봇의 충돌 모형은 몸 전체의 애니메이션 메시 대신 반지름을 가진 수직 몸체로 단순화했습니다.

## 공통 조작과 구현 메모

- 모든 실습은 `q` 또는 `Esc`로 종료합니다.
- PDF의 대문자 명령은 **Shift+해당 알파벳**으로 입력합니다. Caps Lock 대신 Shift를 사용하세요.
- `+`는 일반 키보드의 `Shift+=` 또는 숫자패드 `+`, `-`는 일반 키보드/숫자패드 모두 지원합니다.
- 창 크기를 바꾸면 실제 프레임버퍼/뷰포트 크기로 종횡비를 다시 계산합니다.
- 애니메이션은 초 단위 `dt`를 사용합니다. 충돌 계산은 작은 시간 단계로 나눕니다.
- Core 프로파일에서 사용할 수 없는 `glBegin`, 고정 파이프라인 행렬, GLU 도형 대신 VAO/VBO와 직접 만든 구 메시를 사용했습니다. 강의의 변환 수학은 그대로 적용됩니다.
- 각 실습의 `SelfTest`와 `SmokeStep`는 검증용 함수입니다. 일반 실행의 동작은 바꾸지 않습니다.
- OpenGL 실행 검사에서는 GPU의 attribute 0/1과 VAO-EBO 연결을 조회하고, RGB 정점 색의 보간 및 uniform 색을 실제 프레임버퍼 픽셀과 비교합니다.
- `--self-test`는 창 없이 수학/시뮬레이션을 검사합니다. `--smoke-test --frames 120`은 실제 OpenGL 컨텍스트에서 입력·렌더링을 검사하고 자동 종료합니다. `--capture 경로.ppm`을 함께 주면 마지막 프레임을 저장합니다.
- 화면 안의 상단 안내문·뷰포트 이름은 모두 제거했습니다. 조작키 안내는 콘솔의 한국어 `PrintControls`와 이 문서에서 확인합니다.
- 실습 20의 상자 번호는 본문 필수 조건이므로 유지했습니다.
